# nixos-configurations

One [flake](https://nix.dev/concepts/flakes) that builds every NixOS machine I own.

- **Channel:** `nixos-unstable` (pinned in `flake.lock`)
- **Desktop:** KDE Plasma 6 with Plasma Login Manager
- **Disks:** ext4 on LUKS, systemd-boot, zram swap
- **No Home Manager**, by choice: one user, NixOS only. User settings go through
  NixOS modules and system-wide config files instead.

| Host     | Machine                          |
| -------- | -------------------------------- |
| `laptop` | ThinkPad T480s                   |
| `pc`     | Ryzen 7 7700X, Radeon RX 6950 XT |

## How the repo is laid out

Every host gets all shared modules plus its own folder. Shared modules either
apply everywhere (base) or add a `my.<feature>.enable` switch that a host turns on.

```
flake.nix              inputs, nixosConfigurations.<host>, formatter, checks
flake.lock             pinned nixpkgs revision

hosts/<host>/          only what is specific to one machine
  default.nix            which features are on, hardware tweaks, stateVersion
  hardware-configuration.nix   generated by nixos-generate-config

modules/               shared by every host (imported via modules/default.nix)
  nix.nix                nix daemon: flakes, no channels, gc, optimise
  base.nix               boot, firmware, network, locale, audio, CLI tools
  users.nix              the user account
  unfree.nix             unfree packages, allowed one by one by name
  plasma.nix             my.desktop.plasma.enable  (Plasma, Firefox)
  apps.nix               my.apps.enable            (desktop apps, Steam)
  dev.nix                my.dev.enable             (VS Code, Java, Go, Rust)
  printing.nix           my.printing.enable        (CUPS, Avahi, SANE)

checks/                flake checks behind `nix flake check`
scripts/               helper scripts (see Quality checks)
.github/workflows/     CI: runs scripts/check on every push and PR

CLAUDE.md, .claude/    rules and tooling for Claude Code
.mcp.json              mcp-nixos lookup server for Claude Code
INSTALL.md             step-by-step install of a new machine
```

## Installing a machine

Follow [INSTALL.md](INSTALL.md): partition with LUKS, generate
`hardware-configuration.nix` into `hosts/<host>/`, then
`nixos-install --flake .#<host>`.

## Daily use

Run these from the checkout (`~/nixos-configurations`). `<host>` is `laptop` or `pc`.

```sh
sudo nixos-rebuild switch --flake .#<host>   # build and activate now
sudo nixos-rebuild test   --flake .#<host>   # activate, but no boot entry
sudo nixos-rebuild boot   --flake .#<host>   # activate on next reboot

nix flake update      # move nixpkgs to the latest unstable, then rebuild
nix fmt               # format all .nix files (nixfmt)
scripts/check         # all checks, same as CI
```

**Rolling back:** `sudo nixos-rebuild switch --rollback`, or pick an older
generation in the systemd-boot menu (it shows the last 10).

**New files** must be `git add`ed before the flake can see them.

Old generations are garbage-collected weekly (older than 30 days) and the store
is optimised automatically.

## Adding a program

The rule of thumb is **modules over packages**: if NixOS has a
`programs.<name>` or `services.<name>` module, enable that instead of listing
the package.

1. Look for a module: `scripts/find-module <name>`.
2. Module found: enable it (`programs.<name>.enable = true;`) and configure it there.
3. No module: add the package to `environment.systemPackages` (or
   `users.users.<name>.packages`) with the comment `# no NixOS module` on its line.
4. Unfree: add its name to `modules/unfree.nix`.

Where it goes: a shared file in `modules/` for every machine, or a feature
module behind `my.<feature>.enable` that hosts switch on. `hosts/<host>/` is
only for things truly specific to one machine.

`scripts/check` fails if a listed package has a module or lacks the comment.
Real exceptions go in `packageExceptions` in `checks/default.nix`, with a
reason. The full procedure Claude follows is in
[.claude/skills/add-program/](.claude/skills/add-program/SKILL.md).

## Quality checks

| Tool | What it does |
| --- | --- |
| `nix flake check` | The flake checks in `checks/`: formatting, full evaluation of every host, no NixOS warnings, modules over packages, `# no NixOS module` comments. |
| `scripts/check` | Runs `nix flake check` with `abort-on-warn` (any evaluation warning fails) and rejects untracked `.nix` files. |
| CI | `.github/workflows/check.yml` runs `scripts/check` on every push to `main` and every pull request. |
| `scripts/find-module <name>` | Lists `programs`/`services`/`hardware`/`virtualisation` options and module files for a name, at the locked nixpkgs revision. |
| `scripts/nixpkgs-path` | Prints the store path of nixpkgs at the locked revision, to read module sources. |
| `scripts/nixos-mcp '<json>'` | Asks the mcp-nixos server (search.nixos.org index) from the shell. Run it without arguments for examples. |

A green check means the config evaluates cleanly. It does not prove a change
works on the real machine: test with `nixos-rebuild test` first.

## Working with Claude Code

This repo is set up so Claude Code can change it safely. Claude follows the
rules in [CLAUDE.md](CLAUDE.md) and [`.claude/`](.claude); read those for what
it must do. Changes always arrive as pull requests that CI has checked.

| Path | Purpose |
| --- | --- |
| [CLAUDE.md](CLAUDE.md) | Facts about the machines, hard rules, sources to trust, how to answer. |
| [.claude/rules/](.claude/rules) | User config without Home Manager; Nix style. |
| [.claude/agents/nix-reviewer.md](.claude/agents/nix-reviewer.md) | Reviewer subagent that checks every change before a PR. |
| [.claude/skills/add-program/](.claude/skills/add-program/SKILL.md) | Step-by-step procedure for adding a program. |
| [.claude/settings.json](.claude/settings.json) | Approves the `nixos` MCP server; hooks that format `.nix` on edit and block `git push`/PRs while `scripts/check` fails. |
| [.mcp.json](.mcp.json) | Starts the `nixos` MCP server (mcp-nixos from the locked nixpkgs). |

### Using it locally

1. Install Nix with flakes enabled (on these machines it already is) and
   [Claude Code](https://code.claude.com/docs).
2. Run `claude` in the checkout and accept the prompt to trust the folder.
   Trusting it lets `.claude/settings.json` approve the `nixos` MCP server and
   turn on the hooks.
3. Check with `/mcp` that `nixos` is connected. The first start downloads
   mcp-nixos via `nix run`, so it may take a moment.

**About mcp-nixos:** it is third-party ([utensils/mcp-nixos](https://github.com/utensils/mcp-nixos)),
kept as an extra lookup layer. It answers from the search.nixos.org index, not the
locked revision, so nixpkgs at the lock always wins. To drop it, delete
`.mcp.json` and `scripts/nixos-mcp`, remove `enabledMcpjsonServers` from
`.claude/settings.json`, and remove the mcp-nixos steps from CLAUDE.md,
`.claude/agents/nix-reviewer.md` and `.claude/skills/add-program/SKILL.md`.

In cloud sessions (claude.ai/code) the hooks don't run, so CI is the gate there.
`.mcp.json` loads in single-repo cloud sessions but not in cloud project
threads, which use `scripts/nixos-mcp` instead.
